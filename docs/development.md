# 開発者向け資料

## 構成

- インストールID・Java名前空間: `dev.ryuya.darkapps`。設定authorityは`${applicationId}.config`から生成し、実行時もBuildConfig.APPLICATION_IDを参照。
- 対象: `co.candyhouse.sesame2` と `com.kddi.kdla.jp` のメインプロセスのみ
- セサミ: versionName `3.0.266` / versionCode `906`
- povo: versionName `1.71.0-JP` / versionCode `864`
- compile / target SDK 37、min SDK 36、libxposed API 102

Application.attachの後に公開ContentProviderから配色設定だけを読みます。元のセサミは拡張アプリをqueriesに宣言していないため、設定画面の起動・端末起動・更新時にセサミへURI読み取り権限を付与し、providerの可視性を確保します。対象UIDを確認した明示的なブロードキャスト要求でも権限を再付与できます。Activity生成前に、対象APK内のAppCompatダークオーバーレイとAndroidのダークオーバーレイを重ねます。コンテンツ、入力、クリックリスナー、レイアウト寸法は変更しません。

NativeAppearanceはレイアウト更新時と文字色設定時に、背景と文字のニュートラルカラーを役割別に変換します。色付きインジケーターは維持し、写真・動画・QRコードは変換しません。機器の状態を表す確認済みの同梱アイコンだけは、リソース名の許可リストを使い、白い円と無彩色の線をダーク配色へ変換します。色付きの画素と透明度を維持し、変換結果のキャッシュは32件に制限します。ColorStateListは元の状態指定を保持し、変換キャッシュに上限を設けます。その他の画像では、XMLの単色ベクターUIアイコンのみ着色します。WebViewではAndroidのalgorithmic darkeningを有効にします。セサミはApplication ContextでWebViewを生成するため、ActivityだけでなくApplication側にもネイティブのダークテーマを設定し、prefers-color-schemeを正しく伝えます。タイマーによる走査・画像解析・継続キャプチャはありません。

プロセス内の設定は起動時に固定します。設定変更のためにActivityを再生成しないので、受信済みNFC Intentなどを再実行しません。元アプリへの機器操作APIのフックはありません。

## 保護

未対応バージョンには表示変更を適用しません。初期化に失敗した場合も元のアプリの起動を優先します。連続した描画エラーで表示調整を停止します。過去のApplicationExitInfoに確認できるクラッシュだけを数え、通常の終了・強制停止・プロセス回収を数えません。2分内の3回で停止し、設定画面から解除できます。状態書き込みは自アプリと該当する対象アプリのUIDだけに許可します。

## 複数アプリへの移行

`SupportedApp`でパッケージ・確認済みバージョン・設定・URIを分離します。設定ファイルは`appearance_sesame`と`appearance_povo`に分離します。URIの読み取りと状態更新は管理アプリ自身、または該当ホストのインストール済みUIDだけに許可します。起動時・更新時にアプリごとのURIへ読み取り権限を付与します。

付属ビットマップの調整は対象アプリ別に名前を限定し、キャッシュします。povoの写真・バナー・マスコットなど任意の画像は対象外です。明るい有彩色背景を持つボタンでは黒文字を維持し、黄色背景と白文字の組み合わせを避けます。セサミ・povoの主プロセスのみが対象です。

移行版のreleaseビルド・lint・10件の単体テスト・署名検証は成功しました。実機へ上書き導入し、セサミの有効状態と端末連動設定の引き継ぎを確認しました。

## povoの配色修正と実機確認

初回の共通ビュー変換では、文字が白くなってもCardViewとMaterialの背景色が残り、白地に白文字になる箇所がありました。povo 1.71.0-JPの実機APKで描画経路を確認し、以下を追加しました。

- CardViewの公開APIで背景色を変換。MaterialCardViewには元の形状を維持した面色と1dpの枠線を適用し、有彩色の既存枠は維持。
- このビルドのMaterialShapeDrawableは`Md.g`、定数状態`Md.g$b`の`c`が塗り色、`m(ColorStateList)`が更新メソッド。AppBarLayout・TabLayoutなどの塗り色をこの契約で変換。パッケージとversionCode/versionNameの一致を必須とし、他バージョンには適用しない。
- Drawableの処理済み判定を永続的なスキップから1回の走査内の循環防止へ変更。背景がホストから再設定されたときも反映し、同じ値なら再設定しない。`mutate()`はインスタンスごとに1度だけ行う。
- 通常の着色が効かないPictureDrawableは、確認済みの残量・履歴・通話・SMSのアイコンに限り小さいBitmapへ描き、白色のtintを適用。任意の写真・バナーは処理しない。
- アイコン・カード・通常背景を別の色の役割として扱い、透過と状態リストを維持。黄色など有彩色は変換しない。

Android 17実機では、povoホームのヘッダー・国内／海外タブ・残量／履歴アイコン・SMS／通話カード・下部ナビゲーション、スクロール後のトッピングカードの読みやすさを確認しました。画像の色と黄色の表示を維持し、povoのみOFF→再起動で純正配色へ戻ること、ON→再起動でダーク表示へ戻ることを確認しました。最後はpovoをON・端末連動へ戻しています。セサミの機器一覧もダーク表示と状態色を維持しています。機器操作・購入・契約変更は行っていません。SystemUIのPIDは変更していません。

10件の単体テスト、lint、releaseビルド、55件の依存ライセンス照合、zipalign、固定証明書による署名検証に成功しました。Android 16実機と、対象アプリの全画面の網羅検証は未実施です。

## povoプロフィールの描画

プロフィールはホーム上のフラグメントで、元の背景色`#faf7f7f7`の透明度を維持するとホームの内容が透けます。`profile_list`から`help_root_container`直下のフラグメントルートを辿り、そのColorDrawableを不透明な背景色へ変更します。データバインディングが消去するXMLタグには依存しません。

プロフィール内で`ivNavArrow`と、`tvUnderlinedHelpText`・`tvAddress`・`tvCardNo`のいずれかを直接持つ確認済みの行だけ、既存ColorDrawableをカード面色へ変更します。余白・寸法・クリック処理は維持し、矢印と住所・支払い方法の鉛筆は白に統一します。同じIDを使うお客様情報の黄色い案内アイコンは対象外です。プロフィールでスクロール中に新規作成される行は、ViewのonAttachedToWindow完了時にも変換し、親への所属が確定した時点でプロフィール専用の面色を適用します。これは全体レイアウト通知なしでのRecyclerViewへの追加に対応します。レイアウト後の再バインドは、接続済みビューの背景・背景tint・ImageView描画の設定時にも変換します。既存の再入防止を使い、フレーム単位の走査は追加しません。対象バージョンの一致が前提です。

通知一覧には、画面外でバインドされる行があります。確認済みAPKの公開finalメソッド`RecyclerView.Adapter.bindViewHolder(holder, int)`の完了時に`itemView`全体を変換し、行の表示前に背景・文字・アイコンを揃えます。ホルダー型は難読化されるため、メソッドの引数と公開`itemView: View`フィールドを照合します。確認済みのpovoバージョンがダーク表示を有効にした場合だけ登録します。契約不一致では接続済みビューの方式を残します。

### プロフィール・通知の実機検証

Android 17 / povo 1.71.0-JPで、プロフィール上部・住所・支払い方法・下部の全メニューを往復スクロールしました。鉛筆と矢印の白色、黄色の案内アイコン・支払いロゴ・プロフィール画像の色維持、ホームの透けがなくなることを確認しました。通知の新規行が白く描かれる問題を録画で再現し、バインド完了時の変換後は往復スクロール中の全収録フレームで行の背景が白くならないことを確認しました。レイアウト更新だけを待つ方法では不十分でした。

今回の確認では設定のON/OFFを繰り返していません。対象アプリの開き直しだけで修正を反映し、端末・SystemUIは再起動していません。購入・契約変更・ログアウトは操作していません。端末画像・録画・APK解析資料は公開物に含めません。

## 0.3系のパッケージ整理

インストールID・設定authority・Gradleプロジェクト名・ホスト側クラッシュ保護の保存名をDark App Toolsへ統一しました。旧IDとの互換authorityやActivity aliasは残しません。署名証明書は維持し、秘密鍵のaliasは既存のものを継続使用します。

`tools/migrate_settings.py`はPC側でのみ実行する移行用ツールです。旧版・新版のAPK署名を固定証明書と照合したうえで、ユーザー0の有効状態・テーマ・保護解除時刻を検証して移します。描画状態・古い実行時刻は引き継ぎません。元のXMLとアプリの言語を指定先へ0700/0600でバックアップし、ファイルの所有者とSELinuxラベルを新アプリへ合わせ、移行結果と言語を照合します。既存の新設定を上書きせず、旧アプリの削除も行いません。旧IDは移行ツールと移行説明にのみ残します。

Pythonの試験で、設定の往復、元の既定値、実行状態の除外、破損した値・重複キーの拒否を確認します。アプリ内へroot実行や移行専用Activityを追加していません。

Android 17実機で旧版・新版の署名照合、設定と言語のバックアップ・移行結果の照合に成功しました。Vectorでは旧IDを無効化し新IDを有効化しました。初回は新モジュールがまだ対象へ読み込まれていなかったため、設定の移行成功だけで旧版を消さず、有効化と実際の新IDの読み込みを確認してから進めました。両対象アプリが新authorityへ実行状態を報告し、ダーク表示を適用することを確認した後に旧パッケージを削除しました。ランチャーには新パッケージのActivityだけが残っています。端末・SystemUIの再起動は行っていません。

## セサミの検索ヘッダー

3.0.266の`fg_devicelist.xml`では、`appBarLayout`が白背景のAppBarLayout、`searchEditText`が角丸のEditTextです。AppBarLayoutはXMLのColorDrawableをMaterialの独自形状に置き換えるため、通常のDrawable変換だけでは白い帯が残りました。確認済みのIDに限りViewの公開backgroundTintListで塗り色を指定し、形状・角丸・スクロールフラグは維持します。検索欄は面色・ヒント・単色の虫眼鏡を個別の役割で調整します。機器操作APIは対象外です。
